# 自适应阈值功能说明

## 概述

自适应阈值功能根据不同设备在不同时段的历史数据动态计算异常检测阈值，而不是使用全局固定值。系统自动学习每个设备在不同时间段（夜间/早晨/下午/晚上）的正常波动范围。

## 核心特性

### 1. 时段分类 (TimePeriod)

系统将一天分为 4 个时段：

| 时段 | 时间范围 | 典型特征 |
|-----|---------|---------|
| Night (夜间) | 00:00 - 06:00 | 设备负荷低，温度稳定 |
| Morning (早晨) | 06:00 - 12:00 | 设备启动，温度上升 |
| Afternoon (下午) | 12:00 - 18:00 | 满负荷运行，温度最高 |
| Evening (晚上) | 18:00 - 24:00 | 负荷下降，温度降低 |

### 2. 基线统计 (BaselineStats)

每个设备每个时段每个指标维护以下统计数据：

```go
type BaselineStats struct {
    Mean        float64  // 均值
    StdDev      float64  // 标准差
    Min         float64  // 最小值
    Max         float64  // 最大值
    LastUpdated time.Time // 最后更新时间
}
```

### 3. 增量更新算法

使用指数移动平均进行增量更新，避免重新计算全部历史：

```go
alpha = 1 / (n + 1)
new_mean = old_mean + alpha * (value - old_mean)
new_variance = old_variance + alpha * (delta² - old_variance)
```

**优点**：
- O(1) 时间复杂度
- 内存占用固定
- 自动适应缓慢的数据漂移

## API 接口

### 1. 获取设备基线状态

**GET** `/api/v1/baseline?deviceId={deviceId}[&metric={metric}][&timestamp={ISO8601}]`

**响应示例**：
```json
{
  "deviceId": "device-001",
  "metrics": {
    "temperature": {
      "Night(00-06)": {
        "mean": 25.5,
        "stdDev": 1.2,
        "min": 23.0,
        "max": 28.0,
        "lowerThreshold": 22.5,
        "upperThreshold": 28.5
      },
      "Morning(06-12)": { ... },
      "Afternoon(12-18)": { ... },
      "Evening(18-24)": { ... }
    },
    "vibration": { ... },
    "current": { ... }
  }
}
```

### 2. 训练设备基线

**POST** `/api/v1/baseline/train`

**请求体**：
```json
{
  "deviceId": "device-001",
  "startTime": "2024-01-01T00:00:00Z",
  "endTime": "2024-01-07T23:59:59Z"
}
```

**说明**：使用指定时间范围内的历史数据训练基线。建议训练至少 1 周的数据以获得稳定的基线。

### 3. 设置自适应阈值灵敏度

**POST** `/api/v1/baseline/sigma`

**请求体**：
```json
{
  "sigma": 2.5
}
```

**参数说明**：
- `sigma`：标准差倍数，范围 0.5 - 5.0
- 默认值：2.5
- 数值越大，阈值越宽松，误报越少
- 数值越小，阈值越严格，漏报越少

| Sigma | 置信区间 | 建议场景 |
|-------|---------|---------|
| 1.5 | 86.6% | 严格检测，高灵敏度 |
| 2.0 | 95.4% | 平衡模式 |
| 2.5 | 98.8% | 默认，低误报率 |
| 3.0 | 99.7% | 超宽松，极低误报 |

## 工作流程

### 实时检测流程

```
1. 传感器数据到达
   ↓
2. 更新设备基线（增量学习）
   ↓
3. 根据当前时间确定时段
   ↓
4. 获取该时段的基线统计 (mean, stdDev)
   ↓
5. 计算动态阈值：[mean - sigma*stdDev, mean + sigma*stdDev]
   ↓
6. 检查当前值是否在阈值范围内
   ↓
7. 超出范围 → 生成异常告警并通过 WebSocket 推送
```

### 基线训练流程

```
1. 调用训练 API，指定训练时间范围
   ↓
2. 从 InfluxDB 查询该时间范围的历史数据
   ↓
3. 对每条数据按所属时段更新基线
   ↓
4. 完成训练，返回处理的数据点数量
```

## 置信度计算

异常置信度基于偏离标准差的倍数：

```
偏差倍数 = |value - mean| / stdDev

置信度 = min(100%, max(0%, (偏差倍数 - 1.0) / 2.0 * 100%))
```

**示例**：
- 偏差 1σ 以下：0% 置信度（正常）
- 偏差 2σ：50% 置信度（轻微异常）
- 偏差 3σ 及以上：100% 置信度（严重异常）

## 使用建议

### 1. 初始部署

```bash
# 1. 先使用历史数据训练基线
curl -X POST http://localhost:8080/api/v1/baseline/train \
  -H "Content-Type: application/json" \
  -d '{
    "deviceId": "device-001",
    "startTime": "2024-01-01T00:00:00Z",
    "endTime": "2024-01-07T23:59:59Z"
  }'

# 2. 检查训练后的基线
curl "http://localhost:8080/api/v1/baseline?deviceId=device-001"

# 3. 根据需要调整 sigma
curl -X POST http://localhost:8080/api/v1/baseline/sigma \
  -H "Content-Type: application/json" \
  -d '{"sigma": 2.0}'
```

### 2. 日常运维

- 建议每周重新训练一次基线，适应设备的长期变化
- 定期检查基线统计，观察设备状态的漂移
- 根据误报率动态调整 sigma 值

### 3. 多设备场景

每个设备的基线完全独立：
- 不同型号的设备有各自的正常范围
- 新旧设备的磨损程度不同，基线自动适应
- 特定环境（高温/低温区域）的设备阈值不同

## 性能特性

| 操作 | 时间复杂度 | 说明 |
|------|-----------|------|
| 基线更新 | O(1) | 每个数据点常数时间 |
| 实时检测 | O(1) | 常数时间复杂度 |
| 基线查询 | O(1) | 直接内存访问 |

**内存占用**：每个设备约 1KB（3个指标 × 4个时段 × 5个统计值）

**处理能力**：单台服务器可轻松支持 10,000+ 设备的实时检测

## 与传统方法对比

| 特性 | 全局固定阈值 | 自适应阈值 |
|-----|------------|----------|
| 时段感知 | ❌ 忽略时段差异 | ✅ 分时段动态调整 |
| 设备个性化 | ❌ 所有设备相同 | ✅ 每个设备独立基线 |
| 自适应性 | ❌ 需手动调整 | ✅ 增量自动学习 |
| 误报率 | 较高（一刀切） | 较低（精准匹配） |
| 新设备适配 | 需手动配置 | 自动从零开始学习 |
